# Mission: Respond To Incidents And Own Automated Work

## Outcome

You can stop unsafe activity, contain impact, preserve useful evidence, report
through the correct path, and remain responsible for commands suggested by
software or AI agents.

## Why This Matters

Continuing to experiment after a suspected credential, confidentiality,
access, or data-loss incident can increase harm. Likewise, fluent agent output
is not proof that a command ran or a result is correct.

## Before You Start

Read [Incidents and getting help](https://github.com/IDEALLab/onboarding-IT/blob/docs/llm-agent-overhaul/docs/core/incidents-and-help.md). Use
only fictional scenarios in the evidence.

## Machine And Shell

**Your computer - web browser or text editor.** Do not reproduce a real
incident or run cleanup commands for this mission.

## Steps

For each fictional event below, write the immediate action, containment,
evidence to preserve, and reporting path:

1. A token was committed to a private repository.
2. An AI tool received material that may be confidential.
3. An Euler job is consuming much more shared compute than intended.
4. A shared folder appears to have lost or overwritten files.

Then explain why “the agent said tests passed” is not verification unless you
observed the command, result, scope, and relevant diff yourself.

## Expected Result

Responses prioritize safety and reporting. They avoid posting sensitive details
publicly, hiding mistakes, inventing evidence, or using broad destructive
cleanup.

## Independent Verification

For each scenario, identify the exact point at which you stop changing the
affected system and submit a sanitized report through the documented support
channel. State which sensitive details must stay out of GitHub. Reporting is
asynchronous: submit promptly, but do not wait for someone to be online before
you stop the unsafe action.

## Evidence To Submit

Complete `evidence/core/incidents-ai.md`. Use fictional names and values. Do not
include real logs, tokens, research data, ETH/private identifiers, or screenshots.

## If Blocked

If one scenario resembles a real current event, stop writing the assessment
answer and use the actual incident path. The
[incident scenarios lab](https://github.com/IDEALLab/onboarding-IT/blob/docs/llm-agent-overhaul/docs/labs/incident-scenarios.md) provides
additional safe examples.

## Understand Before Accepting AI Output

An AI tool must not decide whether an incident is harmless, erase evidence, or
contact external services with protected details. You remain responsible for
stopping, preserving safe evidence, submitting the report, and verifying that
the documented incident path was followed.

## Finish And Continue

The controller automatically queues the universal core for human approval on
the permanent draft pull request. No reviewer needs to be present while you do
the mission. When the dashboard says **Awaiting human review**, close it and
return later; after approval, the controller advances to only the responsibility
tracks assigned to you.
